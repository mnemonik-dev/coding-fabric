# Task 03: Master repo clones + sanitized logging filter

## Required Skills
Before starting, load: /skill:python-alchemist

## Description
Clone all six master repos that drive the protocol, and implement the sanitized-logging
middleware that strips secrets before any log line is written to disk or posted back to
Telegram. Anchors user-spec AC40 (sanitizer patterns), tech-spec §2.7. The sanitizer is
the single point of trust for log redaction across every later component.

## What to do
- Clone all six master repos under `~/code/mnemonic-masters/`:
  `mnemonic-core`, `mnemonic-mcp`, `mnemonic-wasm`, `mnemonic-demo-client`,
  `mnemonic-docs`, `mnemonic-loop`. Pin to default branch HEAD.
- Implement `filter.py` exporting a single `sanitize(line: str) -> str` function that
  applies the four regex patterns from tech-spec §2.7 and replaces matches with
  `***REDACTED***`.
- Wrap in a logging.Handler subclass `SanitizedFileHandler` and a Telegram-bot middleware
  `sanitize_outgoing(message)` that runs the same filter on text before send.
- Write unit tests using a corpus of known secret samples (one per pattern) plus negative
  samples (legitimate strings that should not be touched). Assert exactly-once filtering
  per line.

## TDD Anchor
- `tests/test_filter.py::test_redacts_base58_keys` — given a known Solana pubkey, output contains `***REDACTED***` and not the original
- `tests/test_filter.py::test_redacts_jwk_fragment` — given `{"kty":"EC","crv":"P-256","x":"abc","y":"def","d":"ghi"}` keys are redacted
- `tests/test_filter.py::test_redacts_sk_api_anthropic_tokens` — `sk-…`, `api_…`, `ANTHROPIC_…` redacted
- `tests/test_filter.py::test_redacts_telegram_file_urls` — `https://api.telegram.org/file/…` redacted
- `tests/test_filter.py::test_does_not_redact_neutral_text` — sentences with no secrets pass through unchanged
- `tests/test_filter.py::test_idempotent` — running sanitize twice yields the same result (no double-replacement artefacts)

**Dependencies:** Task 01 (base dirs).

**Edge cases:**
- Base58 alphabet excludes `0`, `O`, `I`, `l` — pattern must match `[1-9A-HJ-NP-Za-km-z]`.
- JWK fragments may appear across multiple lines if JSON is pretty-printed — sanitizer
  operates per-line; downstream callers must pre-join JSON before logging.
- Avoid overly aggressive base58 pattern that would match any 32+ alphanumeric strings —
  pair the regex with at least one anchor (e.g., known prefix or known length range).

**Implementation hints:**
- Compile patterns once at module load.
- Keep an opt-in "raw stream" path (root-only filesystem permissions) for emergency
  debugging — but it must not be reachable by the bot or any agent.
