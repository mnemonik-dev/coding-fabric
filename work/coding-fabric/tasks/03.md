# Task 03: Ansible role `vaultwarden`

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Install Vaultwarden via docker-compose, reverse-proxy through Caddy bound to the tailnet
IP only, seed the initial admin token from `infrastructure/secrets/secrets.sops.yml`,
and produce a healthcheck assertion. This is the sole secret store on the VM. Anchors
tech-spec D6, D24, user-spec AC38.

## What to do
- `roles/vaultwarden/tasks/main.yml`:
  - install docker, docker-compose plugin
  - template `docker-compose.yml` with Vaultwarden + Caddy; bind ports to `{{ tailscale_ip }}` only
  - copy `Caddyfile` (TLS via internal CA on tailnet domain `vault.mnemonic-fabric.ts`)
  - read sops-encrypted `VAULTWARDEN_INITIAL_ADMIN_PASSWORD` and set as env var
  - docker compose up -d
  - wait for `/api/health` to return 200 (max 60s)
- Defaults file lists required secrets keys with descriptions

## Acceptance Criteria
- [ ] Role is idempotent (second run: 0 changed)
- [ ] `curl https://vault.mnemonic-fabric.ts/api/health` from operator's tailnet device returns 200
- [ ] `curl https://<vm.public_ip>/api/health` from outside fails (port closed)
- [ ] Initial admin password successfully unlocks Vaultwarden admin panel
- [ ] `ansible-lint` passes

**Edge cases:**
- Re-applying role when Vaultwarden is unhealthy — role must not loop forever; timeout 60s and fail loudly
- Operator already changed admin password manually — role doesn't reset it; only seeds on first install (uses `creates:` guard)

**Implementation hints:**
- Use community.docker collection
- Caddy auto-cert via internal-CA mode (not Let's Encrypt — tailnet domain isn't publicly resolvable)
