# Task 16: PR template + `pr-conformance.yml` workflow templates

## Required Skills
Before starting, load: /skill:github-actions-pro

## Description
Author the canonical PR template (4 sections: what changed, automated validation,
protocol conformance, mnemonic attestation) and the `pr-conformance.yml` GitHub
Actions workflow that enforces both the four-section requirement and the 500-line cap.
These templates are stored here and deployed into each of the 6 master repos by the
`fabric-services` Ansible role at deploy time. Anchors user-spec AC24, tech-spec D16.

## What to do
- `fabric/github-templates/pull_request_template.md` — 4 sections with placeholders + descriptions
- `fabric/github-templates/workflows/pr-conformance.yml`:
  - run on `pull_request` opened/synchronize
  - assert 4 section headings exist in PR body
  - assert `git diff --shortstat base..head` ≤ 500 lines (excluding `Co-Authored-By` and vendored paths from `.github/pr-conformance.config.yml`)
  - dispatcher: read `task_type` from task frontmatter referenced in PR; invoke matching conformance harness (T17)
- `fabric/github-templates/composite-action/` — reusable composite action so per-repo workflows can pin a single tag
- Update molyanov task-creator template to emit `task_type` frontmatter field

## TDD Anchor
- Test PRs in a sandbox repo:
  - 600-line PR → workflow fails with "exceeds 500-line cap"
  - PR missing "Protocol conformance" section → workflow fails with "missing required section"
  - Compliant PR → workflow passes
  - PR with `task_type: schema-cbor` → byte-equivalence harness dispatched
