# Task 18: Test audit

## Required Skills
Before starting, load: /skill:test-master

## Description
Test quality and coverage review across every test suite produced by Tasks 01–15.
Goal: every AC in user-spec.md is either covered by an automated test or has an
explicit documented manual-verification step. Anchors tech-spec §4 Wave 7 T7.3, §5.

## What to do
- Enumerate every AC in user-spec.md (42 total).
- For each AC, locate the test(s) or documented manual verification that cover it.
- For each test suite: assess pyramid balance (unit / integration / end-to-end),
  brittleness, isolation, ability to reproduce production-like behaviour.
- Specific deep dives:
  - Sanitizer test corpus completeness (Task 03) vs the real secret formats in the
    fabric.
  - Workspace-manager API tests (Task 04) — concurrency, atomic state, error paths.
  - Conformance harnesses (Task 13) — fixture corpus coverage, mutation-test posture.
  - Watchdog (Task 14) — each alert class actually triggers on a synthetic condition.
  - Safe-mode (Task 15) — rollback is exercised, not just invoked.
- Write findings to `work/coding-fabric/logs/tasks/test-audit.json`:
  - `severity`: critical | high | medium | low | info
  - `ac_uncovered`: list of ACs without a test
  - `suite_issues`: list of `{area, file, issue, recommendation}`
  - `coverage_summary`: per area

## Acceptance Criteria
- [ ] All 42 user-spec ACs traced to a test or documented manual step.
- [ ] Each test suite has an explicit verdict in the report.
- [ ] Findings include actionable recommendations.
- [ ] Coverage summary present per area.

## Context Files
- [tech-spec.md](../tech-spec.md) — §4 Wave 7, §5 testing strategy
- [user-spec.md](../user-spec.md) — all ACs

## Verification Steps
**Automated:**
- `jq '.ac_uncovered | length' work/coding-fabric/logs/tasks/test-audit.json` returns a number; if non-zero, every entry has a recommendation
- `pytest --collect-only --quiet ~/.fabric/ | wc -l` shows expected test count

## Details
**Files:** read all tests; write only `logs/tasks/test-audit.json`.

**Dependencies:** all Tasks 01–15 completed.

**Edge cases:**
- An AC that is inherently a manual operator check (e.g., AC42 backup restore) — that's
  not a coverage gap; ensure the manual step is documented.
- Conformance harnesses depending on flaky external infra (Solana devnet) — recommend
  mocking adjacent paths but keep one end-to-end smoke per harness.

**Implementation hints:**
- Use `pytest --collect-only` and `coverage run` as inputs; conclusions are still your
  judgement.
