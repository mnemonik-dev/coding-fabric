# Task 09: Ansible role `mnemonic-tg-bridge` (consumes external Rust artefact)

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Install the compiled `mnemonic-tg-bridge` Rust binary (produced by the separate
`mnemonic-tg-bridge` feature) and configure systemd, per-topic configs with the
`cwd: "DYNAMIC"` sentinel resolved against workspace-manager (T08). Until the bridge
artefact exists, role runs in **stub mode** (fail-fast with actionable error).
Anchors tech-spec D8, §2.3 role 11.

## What to do
- `roles/mnemonic-tg-bridge/`:
  - tasks: download binary from `mnemonic_tg_bridge_artefact_url` (sops or repo release),
    install to `/usr/local/bin/mnemonic-tg-bridge`, chmod +x, chown root
  - template `/etc/mnemonic-tg-bridge/config.yml` listing 8 topics with `cwd: "DYNAMIC"`
    and engine choice from §2.4 matrix
  - install systemd unit `mnemonic-tg-bridge.service` with `Restart=on-failure`,
    `Environment=` for workspace-manager URL (`http://{{ tailscale_ip }}:8080`)
  - read `TELEGRAM_BOT_TOKEN` from sops, pass via env
  - sanity-check: invoke `mnemonic-tg-bridge --check-config /etc/mnemonic-tg-bridge/config.yml`
- Stub mode: if `mnemonic_tg_bridge_artefact_url` is unset, fail with message pointing to
  `work/mnemonic-tg-bridge/user-spec.md` for status

- Bridge crashes — `Restart=on-failure` + watchdog alert (T18)

**Implementation hints:**
- Don't bundle the binary in this repo — pull from release asset of the bridge repo
- Version pin matters; bump explicitly when the bridge releases
