# Task 08: Local Mnemonic MCP server + 5 trigger-point wiring

## Required Skills
Before starting, load: /skill:infrastructure-setup

## Description
Install the local Mnemonic MCP server and wire signing hooks at the five trigger points
that form the per-feature attestation DAG. Without this task there is no dog-food
attestation — the protocol does not eat its own corn. Anchors user-spec AC11–AC16,
tech-spec §2.6, D8.

## What to do
- Install the Mnemonic MCP server binary on the VM. Run as a systemd service bound to
  `127.0.0.1`.
- Provision its signing key (stored in Vaultwarden; loaded into the service via
  `LoadCredential=`). No agent may read this key.
- For `protocol-qa` topic only: set `MNEMONIC_MODE=full` so it signs against Solana
  devnet + Arweave testnet. All other topics: `local` mode.
- Implement five hook scripts that call `mnemonic_sign_memory` (memory/receipt/agent.state)
  with the right `parent` references:
  1. `hooks/user-spec.sh` — invoked by `user-spec-planning` Phase 9
  2. `hooks/tech-spec.sh` — invoked by `tech-spec-planning` Phase 6 (`parent=user-spec`)
  3. `hooks/task-complete.sh` — invoked by `do-task` completion (`parent=tech-spec`)
  4. `hooks/pre-deploy.sh` — invoked by `pre-deploy-qa` pass (`parent=task receipts`)
  5. `hooks/post-deploy.sh` — invoked by `post-deploy-qa` pass (`parent=pre-deploy`)
- Wire each hook into the corresponding molyanov skill's success path.

## Acceptance Criteria
- [ ] Mnemonic MCP server reachable on `127.0.0.1` only; systemd unit healthy.
- [ ] Signing key never present on disk outside the systemd-loaded credential.
- [ ] All five hook scripts present and called by the corresponding molyanov skill.
- [ ] `mnemonic_recall --feature=<test-feature>` returns five linked nodes after a stub run.
- [ ] `mnemonic_verify --feature=<test-feature>` reports DAG integrity.
- [ ] `protocol-qa` signs in `full` mode (Solana devnet tx + Arweave testnet tx visible in receipt).

## Verification Steps
**Smoke:**
- `systemctl status mnemonic-mcp.service` shows `active (running)`
- `~/.fabric/mnemonic/hooks/user-spec.sh --feature=stub --artefact=...` returns attestation id
- Pipe through all five hooks with stubbed artefacts; `mnemonic_recall --feature=stub` returns 5 nodes with correct parent chain
- Run in `protocol-qa` topic: `MNEMONIC_MODE=full hooks/task-complete.sh ...` produces receipt with both Solana and Arweave tx fields populated
- Attempt to read signing key from a worktree shell → permission denied

## Details
**Files:**
- `~/.fabric/mnemonic/config.yml` — bind addr, mode default, key reference
- `~/.fabric/mnemonic/systemd/mnemonic-mcp.service` — `LoadCredential=mnemonic-signing-key:bw://…`
- `~/.fabric/mnemonic/hooks/{user-spec,tech-spec,task-complete,pre-deploy,post-deploy}.sh`

**Dependencies:** Task 02 (Vaultwarden seeded with the signing key).

**Edge cases:**
- Network outage on Solana devnet or Arweave testnet — `MNEMONIC_MODE=full` should queue
  the attestation for retry; `local` mode unaffected.
- Hook script exit code is significant: non-zero blocks the molyanov skill's success
  path so a missing attestation does not silently happen.

**Implementation hints:**
- Each hook writes its returned attestation id into `work/<feature>/attestations.yml`
  so the DAG can be reconstructed offline if Mnemonic MCP is down.
