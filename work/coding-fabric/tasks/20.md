# Task 20: Deploy

## Required Skills
Before starting, load: /skill:deploy-pipeline

## Description
Apply the finalised fabric to the cloud VM via the same fabric — this is the first
recursive self-hosting event. The act of deploying the fabric itself is driven through
`mnemonic-loop` and the smoke-gate (Task 15). On success, signs the deploy attestation.
Anchors tech-spec §4 Wave 8 T8.2.

## What to do
- Open a `mnemonic-loop` PR that bundles all fabric configs and binaries (the v0.1 cut).
- Smoke-gate Action (Task 15) runs and must pass.
- Merge the PR.
- The merge runs the deploy workflow: stops services, swaps configs, restarts services,
  posts ops banner.
- Trigger the Mnemonic MCP `post-deploy.sh` hook (Task 08): mode = agent.state,
  parent = pre-deploy receipt.

## Acceptance Criteria
- [ ] `mnemonic-loop` PR opened, smoke-gate passes within budget.
- [ ] Merge happens via the fabric (no human SSH-side install).
- [ ] Services healthy after deploy: workspace-manager, watchdog, mnemonic-mcp, telegram-ai-agent.
- [ ] Mnemonic MCP deploy attestation created with parent = pre-deploy.

**User:**

- Confirm Kaneo and Vaultwarden are reachable via VPN.

## Details
**Files:** none modified directly; this task is an integration exercise driven through
the fabric.

**Dependencies:** Task 19 (pre-deploy QA passed).

**Edge cases:**
- Smoke-gate fails — abort deploy; route to remediation, restart this task afterwards.
- Mid-deploy service restart fails — Task 15 safe-mode auto-engages.
- Mnemonic MCP unreachable at attestation moment — queue offline; surface to ops; do not
  consider deploy "complete" until attestation lands.

**Implementation hints:**
- This is the litmus test for the whole fabric. Treat any deviation as a bug, not a
  workaround.
