# Task 16: Code audit

## Required Skills
Before starting, load: /skill:code-reviewing

## Description
Holistic code-quality review across every artefact produced by Tasks 01–15:
workspace-manager service, sanitizer module, watchdog checks, swarm-bridge,
validator wrappers, conformance harnesses, safe-mode scripts, and the molyanov
configuration surface. Output is analysis-only — fixes happen in a follow-on
remediation wave if findings warrant it. Anchors tech-spec §4 Wave 7 T7.1.

## What to do
- Read every source file produced by Tasks 01–15.
- Apply the 11 review dimensions from the code-reviewing skill:
  correctness, readability, structure, error handling, security implications,
  performance, testability, observability, idiomatic style per language, API design,
  documentation.
- Cross-cutting concerns to specifically check:
  - Consistent sanitizer use (Task 03) at every log/POST site.
  - Consistent workspace-manager client usage (Tasks 05, 10, 14, 15).
  - Consistent error-handling patterns across Python services.
  - No copy-paste of secret-handling logic; everything routes through Task 02 Vaultwarden client.
- Write findings to `work/coding-fabric/logs/tasks/code-audit.json`:
  - `severity`: critical | high | medium | low | info
  - `area`: subsystem (workspace-manager | watchdog | sanitizer | …)
  - `file`, `line`
  - `issue`, `recommendation`

## Acceptance Criteria
- [ ] Every Python module, bash script, GitHub Action workflow, and systemd unit
      produced by Tasks 01–15 has been read.
- [ ] Findings written to `logs/tasks/code-audit.json` with the schema above.
- [ ] If zero findings — explicit "no issues" record with the list of files reviewed.
- [ ] Report is reproducible: the same audit run twice yields the same findings.

## Details
**Files:** read all; write only `logs/tasks/code-audit.json`.

**Dependencies:** all Tasks 01–15 completed.

**Edge cases:**
- A subsystem that ended up un-implemented (deferred) — record as `gap` finding with
  severity `info` rather than skipping.
- Disagreement with a deliberate design decision — record as `info` with rationale, not
  as `medium`.

**Implementation hints:**
- Group findings by area to make the remediation wave faster to drive.
