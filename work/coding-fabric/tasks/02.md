# Task 02: Vaultwarden + Kaneo + Telegram forum/bot + nightly backups

## Required Skills
Before starting, load: /skill:infrastructure-setup

## Description
Stand up the four operational services that every later component depends on:
Vaultwarden (sole secret store), Kaneo (self-hosted task tracker), the Telegram forum and
bot with 8 topics, and nightly backups with a verified test-restore. Anchors user-spec
§4.1 (eight topics), §6 (one-time setup), AC42 (backups), AC31 (Kaneo `/turn-into-task`),
AC38 (Vaultwarden as sole secret store).

## What to do
- Install Vaultwarden via docker-compose. Reverse-proxy through Caddy/Nginx with TLS;
  expose only via VPN (bind 127.0.0.1 + WG interface).
- Install Kaneo similarly; create one project per repo (six projects).
- Create the Telegram bot via @BotFather. Create a forum supergroup with eight topics:
  `core`, `mcp`, `wasm`, `demo-client`, `docs`, `loop`, `protocol-qa`, `ops`. Invite the
  bot, grant it topic-management permissions.
- Seed Vaultwarden with the master credential set: Solana devnet keypair, Irys testnet,
  Telegram bot token, Anthropic API key, OpenAI/Codex key, GitHub PAT, Vault admin.
- Configure nightly backup of the entire `~/.fabric/`, Vaultwarden volume, and Kaneo
  database to an off-VM destination. Provide `backup-verify.sh` that restores the latest
  snapshot to a staging directory and runs integrity checks.
- Run `backup-verify.sh` at least once during Phase 0 and capture the report.

## Acceptance Criteria
- [ ] Vaultwarden reachable at `https://vault.vm/` via VPN; unreachable from internet.
- [ ] Kaneo reachable at `https://kaneo.vm/` via VPN; six projects exist.
- [ ] Telegram bot replies to `/start` in every one of the eight topics.
- [ ] All required credentials present in Vaultwarden.
- [ ] Nightly backup job scheduled; `backup-verify.sh` returns success on a fresh snapshot.

## Verification Steps
**Smoke:**
- `curl --resolve vault.vm:443:127.0.0.1 https://vault.vm/api/health` → 200
- `curl --resolve kaneo.vm:443:127.0.0.1 https://kaneo.vm/api/health` → 200
- `curl -s -X POST "https://api.telegram.org/bot${BOT_TOKEN}/sendMessage" -d "chat_id=${OPS_CHAT_ID}&message_thread_id=${OPS_TOPIC_ID}&text=ping"` → `{"ok":true,...}`
- `bash ~/.fabric/infra/backups/backup-verify.sh` exits 0 and prints "restore ok"

**User:**
- Send `/start` in every topic from your phone; confirm bot replies in each.
- Log into Vaultwarden via VPN; confirm seeded entries appear.
- Log into Kaneo via VPN; confirm six projects.

## Details
**Files (on VM):**
- `~/.fabric/infra/docker-compose.yml` — vaultwarden, kaneo, caddy/nginx services
- `~/.fabric/infra/caddy/Caddyfile` — TLS + VPN-only bind
- `~/.fabric/infra/backups/{cron.sh,restore-test.sh,backup-verify.sh}`

**Dependencies:** Task 01 (VM, VPN, base dirs).

**Edge cases:**
- Telegram forum topics have numeric `message_thread_id` — store the mapping in
  `~/.fabric/infra/telegram-topics.yml` for later tasks.
- Backup destination must NOT be the same cloud region as the VM.

**Implementation hints:**
- Use a per-topic alias in `telegram-topics.yml` so later tasks reference by topic name.
- Snapshot Vaultwarden's master key only into the operator's offline password manager —
  do not store on the VM.
