# Task 12: task_type field + PR template enforcement

## Required Skills
Before starting, load: /skill:github-actions-pro

## Description
Introduce a `task_type` field in task frontmatter and enforce the four-section PR template
(what changed, automated validation, protocol conformance, mnemonic attestation) plus the
500-line cap via a CI check in all six repos. Anchors user-spec AC24, tech-spec §3 D10,
§4 Wave 5.

## What to do
- Extend the molyanov task frontmatter schema with `task_type: schema-cbor | crypto-primitive
  | mcp-surface | wasm-bindings | full-mode-integration | crypto-crate-bump | loop-fabric | other`.
- Update task-creator's templating to accept and write this field.
- Author `pull_request_template.md` in each of the six master repos with the four
  required sections as headings.
- Add `.github/workflows/pr-conformance.yml` to each repo that runs on PR open/update:
  - Asserts the four section headings exist in PR body.
  - Asserts `git diff --shortstat base..head | awk '{print $4+$6}'` ≤ 500.
  - Fails with a clear message indicating which check failed.
- Update molyanov's task-creator skill to write `task_type` for every task it produces.

## Acceptance Criteria
- [ ] Task template includes `task_type` field; task-creator emits it.
- [ ] All six repos have `pull_request_template.md` with the four sections.
- [ ] `pr-conformance.yml` exists in all six repos.
- [ ] PR missing any of the four sections fails the workflow.
- [ ] PR with more than 500 changed lines fails the workflow.
