# Task 02: Ansible roles `base` + `tailscale`

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Two foundational Ansible roles that prepare the freshly-provisioned VM for everything
else. `base` does OS hardening; `tailscale` joins the VM to the tailnet so all later
roles (Vaultwarden, Kaneo, etc.) can bind to the tailnet IP and stay off the public
internet. Anchors tech-spec D2, D4, user-spec AC1–AC3, AC41.

## What to do
- `roles/base/`:
  - tasks: ufw deny default + allow Tailscale; unattended-upgrades; create operator user
    `op` with sudo NOPASSWD only for explicit Ansible-managed commands; disable root SSH
    + password auth; create `~/code/` and `~/.fabric/` base dirs
  - handlers: reload sshd, reload ufw
- `roles/tailscale/`:
  - tasks: add Tailscale apt repo, install tailscaled, `tailscale up --authkey
    {{ tailscale_authkey }} --hostname mnemonic-fabric --accept-routes`
  - register tailnet IP in fact `tailscale_ip` for later roles
  - handlers: restart tailscaled

## Acceptance Criteria
- [ ] Both roles are idempotent (second run shows zero changes)
- [ ] After `base`: `ssh root@vm` over public IP fails; SSH only over tailnet
- [ ] After `tailscale`: `tailscale status` on VM shows online; tailnet IP fact is set
- [ ] `ufw status` shows only Tailscale-permitted rules
- [ ] Lint passes: `ansible-lint roles/base roles/tailscale`
