# Task 05: telegram-ai-agent DYNAMIC sentinel patch

## Required Skills
Before starting, load: /skill:python-alchemist

## Description
Teach `telegram-ai-agent` to resolve the new `cwd: "DYNAMIC"` sentinel by calling
workspace-manager's `POST /worktree`. Without this, no topic can spawn an engine inside
an isolated worktree. Anchors user-spec AC6, tech-spec §2.5, D2.

## What to do
- Patch the agent's topic-config loader to recognise `cwd: "DYNAMIC"` and skip path
  validation at config-load time.
- At engine-spawn time, derive a `task_id` from the originating Telegram message
  (`{topic}-{message_id}` or Kaneo card id if linked), then call
  `POST http://127.0.0.1:8080/worktree` with `{task_id, repo, base_ref, topic}`.
- Use the returned `cwd` to launch the CLI engine. Cache the resolution for the lifetime
  of the task.
- On task end (engine exit, `/cancel`, timeout), call `DELETE /worktree/{task_id}`.
- Log all calls via the sanitizer middleware (Task 03).

## Details
**Files:**
- `~/code/mnemonic-masters/telegram-ai-agent/agents/config_loader.py` — DYNAMIC handling
- `~/code/mnemonic-masters/telegram-ai-agent/agents/topic_runtime.py` — resolve + cleanup hooks
- `~/code/mnemonic-masters/telegram-ai-agent/agents/workspace_client.py` — HTTP wrapper around workspace-manager

**Dependencies:** Task 04 (workspace-manager API is the contract this task consumes).

**Edge cases:**
- Network blip between agent and workspace-manager — retry once with backoff; on failure post to ops.
- Engine crashes before cleanup — agent must guarantee DELETE in a `finally` block.
- Repeated handler invocations for the same Telegram message — idempotent by `task_id`.

**Implementation hints:**
- Use `httpx.Client(timeout=5.0)` with retries via `tenacity`.
- Key the resolution cache by `task_id`, not by message id, so a Kaneo-attached task survives a Telegram-message edit.
