# Task 12: Ansible role `mnemonic-mcp` (server + 5 trigger-point hooks)

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Install the local Mnemonic MCP server, provision its signing key via systemd
`LoadCredential` from Vaultwarden (T03), set up `MNEMONIC_MODE=full` for `protocol-qa`
topic only, and install the 5 trigger-point hook scripts that produce the per-feature
DAG. Anchors user-spec AC11–AC16, tech-spec §2.3 role 9, §2.6, D14.

## What to do
- `roles/mnemonic-mcp/tasks/main.yml`:
  - install MCP binary (pin version)
  - install systemd unit with `LoadCredential=mnemonic-signing-key:vault://...`
  - bind to `127.0.0.1:7777` (mnemonic mcp default)
  - render 5 hook scripts under `/etc/mnemonic-mcp/hooks/`:
    `user-spec.sh`, `tech-spec.sh`, `task-complete.sh`, `pre-deploy.sh`, `post-deploy.sh`
  - register hooks with molyanov skill success paths (config injection)
- protocol-qa: render `/etc/mnemonic-mcp/protocol-qa.env` with `MNEMONIC_MODE=full`

## Acceptance Criteria
- [ ] Role idempotent
- [ ] `systemctl is-active mnemonic-mcp` returns `active`
- [ ] Signing key never appears on disk outside systemd credential
- [ ] All 5 hooks present, executable, log to sanitizer
- [ ] Stub end-to-end test: synthetic invocation of all 5 hooks yields a 5-node DAG via `mnemonic_recall`
- [ ] `ansible-lint` passes

## Details
**Files:**
- `infrastructure/ansible/roles/mnemonic-mcp/{tasks,defaults,templates,files,molecule}/`

**Edge cases:**
- Solana devnet RPC outage in `full` mode — hook queues attestation for retry; local-mode unaffected
- Hook non-zero exit blocks molyanov skill success — by design; missing attestation can never silently happen
- Signing key not in Vaultwarden — role fails with actionable error pointing to bootstrap checklist

**Implementation hints:**
- Each hook writes its attestation id to `work/<feature>/attestations.yml` (DAG reconstructable offline)
- Use existing Mnemonic MCP server from `mnemonic-mcp` master clone
