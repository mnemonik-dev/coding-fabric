# Task 04: workspace-manager HTTP service

## Required Skills
Before starting, load: /skill:fastapi-expert

## Description
Implement the central glue service of the fabric: a FastAPI HTTP service that owns
per-task git worktrees, materialises a per-worktree `.env` from Vaultwarden, mounts the
shared sccache, enforces the 10-active cap, and exposes the resolver API consumed by
`telegram-ai-agent` (Task 05) and the swarm bridge (Task 10). Anchors tech-spec §2.5
contract, user-spec AC4–AC7, AC38 (per-worktree .env), AC42 / TR1 (single point of
failure mitigated by ops back-channel).

## What to do
- Implement the HTTP contract from tech-spec §2.5 exactly:
  - `POST /worktree` — create worktree under `~/code/mnemonic-workspaces/<task_id>` from
    `~/code/mnemonic-masters/<repo>`; mount sccache; pull secrets via Vaultwarden CLI for
    the requested topic; write `.env`; record in `state.json`. Return 200 with `cwd`.
  - `DELETE /worktree/{task_id}` — remove `.env`, `git worktree remove`, deregister.
  - `GET /worktree/{task_id}` / `GET /worktrees` — read from `state.json`.
  - `GET /health` — sccache mount status, vault reachability, capacity used.
- Enforce capacity cap = 10 active (return 409 with body `{"error":"capacity"}`).
- Persist state to `~/.fabric/workspace-manager/state.json` (atomic writes).
- Systemd unit listens on `127.0.0.1:8080` only — never expose externally.
- Vaultwarden client: use Bitwarden CLI (`bw`) with a sealed session token stored in
  systemd `LoadCredential=` mechanism — agents must not be able to read it.

## Details
**Files:**
- `~/.fabric/workspace-manager/main.py` — FastAPI app
- `~/.fabric/workspace-manager/worktree.py` — `git worktree add/remove` wrappers + sccache mount
- `~/.fabric/workspace-manager/vault.py` — Bitwarden CLI wrapper (session via systemd credential)
- `~/.fabric/workspace-manager/state.py` — atomic state.json
- `~/.fabric/workspace-manager/systemd/workspace-manager.service` — `LoadCredential=bw-session:...`
- `~/.fabric/workspace-manager/tests/`

**Dependencies:** Task 01 (base dirs), Task 02 (Vaultwarden), Task 03 (master clones; sanitizer for log lines).

**Edge cases:**
- Concurrent POST for the same `task_id` — return 409 with `already_exists`.
- DELETE on unknown `task_id` — return 404.
- Vaultwarden unreachable — return 409 `vault_unreachable` and log to ops via sanitizer.
- Sccache directory missing — `GET /health` returns degraded but service stays up.

**Implementation hints:**
- Use `git worktree add --detach <base_ref>` to avoid local branch noise.
- Generate `.env` from a topic-specific Vaultwarden collection (e.g., `mnemonic/topic/core`).
- Set `.env` file mode to `0600`, owner `op`.
- Reject `task_id` that does not match `^[A-Z0-9-]{3,40}$` — defence against path traversal.
