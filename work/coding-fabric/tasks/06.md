# Task 06: Ansible role `restic-backups`

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Install Restic, configure nightly backups of `~/.fabric/`, Vaultwarden + Kaneo data,
master clones, and the OpenTofu state file to an off-site repository (Hetzner Storage
Box or S3-compatible — operator's choice via variable). Ship a `backup-verify.sh` and
run it once during Phase 0 to assert the snapshot is restorable. Anchors tech-spec D28,
user-spec AC42, TR8.

## What to do
- `roles/restic-backups/tasks/main.yml`:
  - install restic binary
  - template `/etc/restic/repo.env` from sops vars (`RESTIC_REPOSITORY`, `RESTIC_PASSWORD`)
  - install `/usr/local/bin/fabric-backup.sh` and `/usr/local/bin/backup-verify.sh`
  - register systemd timer `fabric-backup.timer` (OnCalendar `*-*-* 02:30:00`, RandomizedDelaySec 30min)
- Defaults expose:
  - `restic_paths` (list of dirs to back up)
  - `restic_keep_daily`, `restic_keep_weekly`, `restic_keep_monthly`
- Healthcheck: run `restic snapshots` and assert at least one exists (skip on first-ever run if `--allow-empty` true)

## Acceptance Criteria
- [ ] Role idempotent
- [ ] Backup runs without error: `bash /usr/local/bin/fabric-backup.sh` exits 0
- [ ] Verify script restores latest snapshot to staging dir without error
- [ ] `ansible-lint` passes
- [ ] Retention policy applied (`restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6`)

- `infrastructure/secrets/secrets.sops.yml` (extended)

**Edge cases:**
- Network outage to remote repo — script retries 3 times; on persistent failure, posts to ops topic
- Restic password loss = data loss — explicit warning in defaults; password stored in ops's password manager AND sops
- Concurrent backup attempts — restic native locking

**Implementation hints:**
- Use `geerlingguy.restic` Ansible role as inspiration but keep ours bespoke (one role > nested galaxy deps)
- `backup-verify.sh` restores last snapshot to `/tmp/restore-test-$DATE` and asserts a known file's checksum
