# Task 17: Security audit

## Required Skills
Before starting, load: /skill:security-auditor

## Description
OWASP Top 10 plus secret-handling-specific checks across every component delivered by
Tasks 01–15. Special emphasis on the four areas where this fabric concentrates risk:
Vaultwarden interaction, per-worktree `.env` materialisation, sanitized logging, and the
agent trust boundary. Anchors tech-spec §4 Wave 7 T7.2.

## What to do
- Run a structured OWASP pass over each service and script.
- Specific deep dives:
  1. **Vaultwarden interaction** — credential never reaches stdout, env, or process
     listing; session token loaded via systemd `LoadCredential`.
  2. **`.env` materialisation** — file mode 0600, owner `op`, deleted on cleanup, never
     read by agents directly.
  3. **Sanitized logging** — every log emission goes through the filter; raw paths are
     root-readable only; no bypass exists in error paths.
  4. **Agent trust boundary** — agents cannot write outside their worktree, cannot read
     Vaultwarden, cannot push to `main` of any repo, cannot trigger production deploy.
- Validate: HTTP services bind to 127.0.0.1; no service exposes anything to the public
  internet outside VPN.
- Validate: signed-key paths and Mnemonic MCP credential handling.
- Write findings to `work/coding-fabric/logs/tasks/security-audit.json` with severity,
  area, file/line, exploit-scenario, fix.

## Acceptance Criteria
- [ ] OWASP Top 10 pass complete across all components.
- [ ] Four deep-dive areas have explicit verdicts in the report.
- [ ] No critical or high finding without an attached fix recommendation.
- [ ] All findings traceable to a specific file:line.
- [ ] Service-binding scan confirms no public exposure.

## Details
**Files:** read all components; write only `logs/tasks/security-audit.json`.

**Dependencies:** all Tasks 01–15 completed.

**Edge cases:**
- Deliberate "trust the operator" decisions (e.g., operator can SSH and run anything) —
  document as accepted risk with rationale, severity `info`.
- A finding that the sanitizer regex may not catch some unknown future secret format —
  record as `medium` with a recommendation to extend pattern list.

**Implementation hints:**
- Use known-secret fixture corpora (Task 03) to probe sanitizer in real call sites, not
  just unit tests.
- Run `bandit` and `semgrep` (with sensible rulesets) over Python code as additional
  signal — these are inputs to your judgement, not gates.
