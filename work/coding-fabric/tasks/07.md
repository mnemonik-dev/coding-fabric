# Task 07: `fabric/logs/sanitizer/` — Python module + tests

## Required Skills
Before starting, load: /skill:python-alchemist

## Description
The single point of trust for log redaction across every later component. Strips secrets
(base58 keys, JWK fragments, `sk-`/`api_`/`ANTHROPIC_` tokens, Telegram file URLs) from
every log line before disk-write or Telegram send. Anchors tech-spec D26, §2.7, user-spec AC40.

## What to do
- `fabric/logs/sanitizer/filter.py` — module exporting `sanitize(line: str) -> str` and four
  compiled patterns. Replacement: `***REDACTED***`.
- `fabric/logs/sanitizer/handler.py` — `SanitizedFileHandler` subclass of `logging.FileHandler`
- `fabric/logs/sanitizer/tg_middleware.py` — `sanitize_outgoing(message: str) -> str` for bot send
- `fabric/logs/sanitizer/tests/test_filter.py` — corpus of secret samples (positive) + neutral
  samples (negative) + idempotency check

## TDD Anchor
- `test_redacts_base58_solana_pubkey` — known 44-char Solana pubkey replaced
- `test_redacts_jwk_fragment` — `kty`/`crv`/`x`/`y`/`d` field values stripped
- `test_redacts_sk_api_anthropic_tokens` — all three prefixes
- `test_redacts_telegram_file_urls` — `https://api.telegram.org/file/...`
- `test_does_not_redact_neutral_text` — short sentences pass through
- `test_idempotent` — `sanitize(sanitize(x)) == sanitize(x)`
- `test_no_double_replacement` — single pass replaces each match once

**Edge cases:**
- Base58 false positives on long alphanumeric strings — require length 32–44 + base58 alphabet (excludes 0, O, I, l)
- Multi-line JWK pretty-printed JSON — sanitizer is per-line; document that callers must single-line JSON before logging
- Unicode-normalised secrets — patterns operate on raw bytes/str; document the limitation

**Implementation hints:**
- Compile patterns at module load
- No third-party deps beyond stdlib `re` and `logging`
