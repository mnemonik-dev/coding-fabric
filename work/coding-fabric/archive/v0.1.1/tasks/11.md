# Task 11: Validator delegation to ruflo plugins

## Required Skills
Before starting, load: /skill:python-alchemist

## Description
Wire molyanov's validators so that `skeptic` delegates to ruflo `jujutsu`,
`security-auditor` to ruflo `security-audit`, and `post-deploy-qa` to ruflo `browser`.
Validator reports stay in molyanov format; delegation is transparent. Anchors user-spec
AC10, tech-spec §3 D7, §4 Wave 4.

## What to do
- For each of the three validators, write a thin Python wrapper module that:
  1. Reads validator inputs in molyanov format.
  2. Invokes the corresponding ruflo plugin via its CLI/MCP entrypoint.
  3. Normalises the plugin output back into molyanov's JSON report schema.
  4. Emits any auxiliary trace lines through the Task 03 sanitizer.
- Replace the existing validator entrypoints in molyanov skills to route through these
  wrappers.
- Provide a `--dry-run` flag that prints which plugin would be invoked, for debugging.

## TDD Anchor
- `tests/test_skeptic_wrapper.py::test_invokes_jujutsu` — verifies subprocess called with jujutsu args
- `tests/test_skeptic_wrapper.py::test_normalises_output_to_molyanov_schema` — output matches JSON schema
- `tests/test_security_wrapper.py::test_invokes_security_audit` — security-audit binary invoked
- `tests/test_security_wrapper.py::test_propagates_findings` — known-vulnerable fixture yields findings in molyanov format
- `tests/test_postdeploy_wrapper.py::test_invokes_browser` — browser plugin invoked
- `tests/test_*_wrapper.py::test_failure_logged_via_sanitizer` — error path uses sanitizer

## Acceptance Criteria
- [ ] All three wrappers exist and pass their tests.
- [ ] Running a molyanov validator (e.g., `claude /security-audit`) shows ruflo plugin in stderr trace.
- [ ] Validator reports contain a `delegated_to` field naming the underlying ruflo plugin.
- [ ] Errors from ruflo plugins propagate as molyanov-formatted failures.
