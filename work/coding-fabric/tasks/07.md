# Task 07: molyanov-ai-dev install + Project Knowledge canonical

## Required Skills
Before starting, load: /skill:infrastructure-setup

## Description
Install the molyanov-ai-dev methodology stack across all eight topics and enforce that
its Project Knowledge directory is the canonical source — ruflo substrate must not
overwrite PK paths. Anchors user-spec AC28, tech-spec D12.

## What to do
- Install molyanov-ai-dev slash commands and skills globally (`~/.claude/skills`) and
  ensure the engines in all eight topics see them.
- Add a pre-write hook that rejects any ruflo or external write under
  `.claude/skills/project-knowledge/references/` in any worktree. On reject: non-zero
  exit + post structured alert to the `ops` topic via Telegram bot.
- Initialise PK in each of the six master clones (if not already present) using
  `/init-project-knowledge` so every worktree inherits the same structure.

## Acceptance Criteria
- [ ] `claude --help` (or equivalent) shows molyanov skills available in every topic.
- [ ] Attempted ruflo write to a PK path is rejected with non-zero exit.
- [ ] An ops-topic alert is posted on every rejection.
- [ ] All six master repos have a populated `.claude/skills/project-knowledge/references/` dir (or a placeholder explaining why it is intentionally empty).

## Details
**Files:**
- `~/.fabric/molyanov/global.yml` — points to global skills, sets defaults
- `~/.fabric/molyanov/hooks/pk-guard.sh` — pre-write hook, exit 1 on PK paths
- `~/.fabric/molyanov/hooks/ops-notify.sh` — wrapper that posts to `ops` via bot token

**Dependencies:** Task 06 (ruflo installed; flags pinned).

**Edge cases:**
- Hook must not trigger on read-only operations (`git diff`, `cat`).
- Hook must not interfere with operator's own SSH-shell edits — limited to ruflo's
  invocation context (check env var `RUFLO_SESSION=1` to scope).

**Implementation hints:**
- Hook script under 30 lines; pure bash; sanitize logged paths via the Task 03 filter.
