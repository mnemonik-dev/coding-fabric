# Deploy O2 through GitHub Actions

This provisions a **dedicated Ubuntu 22.04 or 24.04 AMD64 VM**. It runs the published
MCP image for source `e8b6e2b`, pinned by digest, with its own key, database and
Caddy HTTPS endpoint. Both container images are pinned. Payments start disabled
(`PAYMENT_MODE=none`). Like the production `mnemonik-server` role, it anchors
on Solana mainnet and stores on Arweave through ArDrive Turbo. The main fabric playbook,
production services and Tailscale are not invoked.

## 1. Supply encrypted connection settings

Create `infrastructure/secrets/o2.sops.yml` using `sops` from the repository root.
The encryption rule is in `.sops.yaml`. Use the field names in
[`o2.sops.yml.template`](../secrets/o2.sops.yml.template):

```yaml
host: SECOND_VM_IP
admin_user: EXISTING_ADMINISTRATOR
domain: mcp-o2-staging.YOUR_DOMAIN
authorized_key: ssh-ed25519 PUBLIC_KEY_FOR_RESTRICTED_MNEMONIK_USER
backup_recipient: age1YOUR_OFF_HOST_BACKUP_PUBLIC_RECIPIENT
```

The IP is encrypted and used only in an in-memory Ansible inventory. Point the
domain's DNS to this VM; DNS for a public endpoint still reveals its IP. Allow
80/443 for TLS and SSH from the selected runner. Do not expose port 3000.

Initial provisioning uses an existing administrator with noninteractive sudo
(or root). The `mnemonik` account does not provision the machine. The playbook
removes its supplementary groups and replaces `/etc/sudoers.d/mnemonik` with
five fixed commands for this stack. Audit/remove any separately created grants
to the same account; this does not revoke other sudoers files or old sessions.

If `admin_user` is `mnemonik` (an existing account with noninteractive sudo),
the playbook leaves its groups, password and sudoers rules unchanged, so
`mnemonik` keeps full root on the VM.

## 2. Configure GitHub environment `paywall-staging`

The workflow uses the existing `paywall-staging` environment where the O2
credentials are configured. Add these environment secrets:

| Secret | Value |
|---|---|
| `SOPS_AGE_KEY` | Existing identity that decrypts the O2 SOPS file |
| `O2_ADMIN_SSH_KEY` | SSH private key authorized for `admin_user` |
| `O2_SSH_KNOWN_HOSTS` | Verified host key using alias: `mnemonik-o2 ssh-ed25519 AAAA...` |

Obtain the SSH host public key through the VM console or an already trusted
admin connection (`/etc/ssh/ssh_host_ed25519_key.pub`). The workflow requires
host-key checking; it does not trust a fresh network key scan.

Default runner is `ubuntu-24.04`. If its SSH traffic is not allowed by your
firewall, set environment variable `O2_RUNNER` to the label of a trusted runner
with permitted access. The job installs Linux AMD64 tooling. It does not create
firewall rules or enroll Tailscale nodes. Public GHCR pulls require no registry
credential; a private package would need administrator-configured Docker login.

## 3. Prepare and back up

Commit/push the workflow, playbook, bootstrap/control/backup scripts and encrypted
configuration. A new manually dispatched workflow must first exist on the
repository's default branch to appear in Actions.

Run **Deploy MCP O2 → prepare**. It installs dependencies, generates keys once,
and uploads **mcp-o2-encrypted-key-backup**. It does not start MCP. Download the
artifact and retain an additional encrypted copy outside GitHub and the VM.
GitHub artifact retention is 30 days; it is not the long-term backup destination.

Verify decryption locally without printing key contents:

```bash
set -o pipefail
age --decrypt -i /secure/path/backup-age-key.txt mcp-o2-keys.tar.gz.age | tar -tzf -
```

The listing must contain `secrets/id.json`, `secrets/mcp.env`, `operator.json`,
`compose.json`, and `Caddyfile`. Keep the age decryption identity off the VM.
The operator identity and JWT/refresh secrets must survive updates. This initial
archive does **not** contain the live database; add consistent SQLite/WAL backups
before retaining test history. Client signing/decryption keys are separate.

## 4. Start

Run **Deploy MCP O2 → start** from the **same commit/ref** as prepare. Supply the
successful prepare run ID and select the backup-verification checkbox only after
the verification above. The job downloads that backup, pulls pinned images,
starts O2 and checks public HTTPS health. It does not upload memories or spend funds.

Endpoint: `https://YOUR_O2_DOMAIN/mcp`. Authenticate clients for this origin.
The administrator can read `/opt/mnemonik-o2/operator.json` for the public identity
pin and add it to the client's configured operator list. Never copy O1's identity.

The restricted account can run only:

```bash
sudo /usr/local/sbin/mnemonik-o2 install
sudo /usr/local/sbin/mnemonik-o2 start
sudo /usr/local/sbin/mnemonik-o2 stop
sudo /usr/local/sbin/mnemonik-o2 restart
sudo /usr/local/sbin/mnemonik-o2 status
```

`install` pulls the root-configured images; it accepts no image, path or command
arguments. Root owns the Compose file, configuration and helper. The account
is not in the Docker group and cannot edit the pinned deployment. Initial
preparation preserves existing O2 files; it is not an image-upgrade mechanism.
Container failure leaves state in place; no automatic database rollback occurs.

## 5. Upgrade the MCP image

Change `IMAGE` in `bootstrap-o2.py` to the reviewed digest, merge, then run
**Deploy MCP O2 → upgrade**. This action needs no backup inputs, because it does
not change the identity, secrets, data or Caddy. It changes only the MCP image in
`/opt/mnemonik-o2/compose.json` and keeps the old file as `compose.json.prev`.

The job pulls the image, restarts O2 and checks public HTTPS health. Then it
calls `mnemonic_operator_proof` with a fresh nonce. The returned key and origin
must match `/opt/mnemonik-o2/operator.json`. If any check fails, the job restores
`compose.json.prev`, restarts the previous image and fails. Verify the proof
signature independently with `scripts/check-operators.mjs` in the monorepo.

## Storage and payment boundary

New shared ingestion no longer requires a Solana memo transaction. Uploads go
to the fixed ArDrive Turbo endpoint as ANS-104 items signed with the operator's
Ed25519/Solana-format keypair, so the storage identity is still the Solana key.
There is no Turbo test network: every upload is permanent on Arweave mainnet.
O2 uses the production settings: `ANCHORING_NETWORK=mainnet` (it selects only
the Solana memo network), Solana mainnet-beta RPC, and
`ARWEAVE_GATEWAY_URL=https://arweave.net` as the read-only primary gateway.
Chain stats read `https://arweave.net/graphql` and `https://arweave.net`.
These settings need an MCP image built with Turbo uploads (monorepo
`feat/turbo-arweave-uploads`); the pinned `e8b6e2b` image predates it, so
bump the image before relying on them.

Boot needs no wallet funding. Items up to 105 KiB upload free (10 MiB lifetime
per wallet or IP); larger items need Turbo credits on the O2 identity's wallet,
otherwise Turbo answers HTTP 402. Solana memo anchoring spends SOL from the same
wallet, which starts empty. With `PAYMENT_MODE=none` clients are not charged,
so any authorized client can spend that balance. Live upload,
index visibility, recovery, browser authentication and paid acceptance remain
separate checks. Later paid staging needs Paywall configuration and test funds.

This is repeatable configuration with pinned container artifacts, not a claim
of bit-identical OS provisioning: Ubuntu security/package updates still apply.
