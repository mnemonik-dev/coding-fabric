# Task 14: fabric-watchdog (9 alert classes, 5-min cadence) + /turn-into-task

## Required Skills
Before starting, load: /skill:python-alchemist

## Description
Implement the watchdog that scans fabric health every 5 minutes, alerts the `ops` topic
for any anomaly across nine classes, and the `/turn-into-task` Telegram bot command that
converts an alert into a Kaneo card. Operational toil becomes work items inside the same
fabric. Anchors user-spec AC29–AC32, AC31, tech-spec §3 D13, D14, D25.

## What to do
- Author Python checks (one module per alert class) under `~/.fabric/watchdog/checks/`:
  1. `orphaned_worktrees.py` — worktrees on disk without a workspace-manager record
  2. `hung_tmux.py` — tmux sessions older than 12h with no recent activity
  3. `solana_rpc.py` — RPC endpoint unresponsive
  4. `irys_balance.py` — balance below threshold
  5. `stale_swarms.py` — ruflo swarms idle past TTL
  6. `disk_pressure.py` — `du ~/code/mnemonic-workspaces` ≥ 75/85/90% of 50 GB
  7. `master_drift.py` — master clone HEAD diverged from origin
  8. `stale_prs.py` — open PR with no activity > 7 days
  9. `failed_attestation.py` — Mnemonic MCP queue contains failed signings
  10. `stale_lkg.py` — last-known-good tag older than 7 days
- Schedule via systemd timer `fabric-watchdog.timer`, OnCalendar `*:0/5`.
- Each alert posts to `ops` via Telegram bot with: severity, class, evidence, alert_id.
- Implement `/turn-into-task <alert_id>` Telegram bot command that creates a Kaneo card
  in the appropriate project (derived from the alert class).
- Apply Task 03 sanitizer to every alert body.

## Details
**Files:**
- `~/.fabric/watchdog/checks/*.py` (10 files)
- `~/.fabric/watchdog/scheduler.py` — entrypoint that runs all checks
- `~/.fabric/watchdog/telegram.py` — post-to-ops
- `~/.fabric/watchdog/kaneo.py` — create-card client
- `~/.fabric/watchdog/turn_into_task.py` — bot command handler
- `~/.fabric/watchdog/systemd/{fabric-watchdog.service,fabric-watchdog.timer}`
- `~/.fabric/watchdog/state/alerts.json` — alert id → context cache

**Dependencies:** Task 02 (Kaneo + Telegram bot), Task 04 (workspace-manager — checked).

**Edge cases:**
- Bot rate-limits if all 9 alert classes fire simultaneously — batch into a single
  digest message when > 3 fire in one tick.
- Alert id collision unlikely (UUID4) but Kaneo card creation must be idempotent.
- Watchdog must not deadlock on a failing check — each check has a per-process 30s timeout.

**Implementation hints:**
- Each check returns `Alert | None`; scheduler aggregates and sends batch.
- Persist alert ids for at least 24h so `/turn-into-task` can look them up later.
