# Task 01: Provision VM, VPN, and access controls

## Required Skills
Before starting, load: /skill:infrastructure-setup

## Description
Provision the single cloud VM that hosts the entire coding fabric and lock administrative
access behind VPN. This is the foundation for every later task: workspace-manager, ruflo,
mnemonic-mcp, watchdog, and all repository worktrees live here. Anchors user-spec AC1–AC3
(Telegram everywhere), AC41 (agent trust boundary starts with VM perimeter), §6 Manual
setup, §7 Deploy approach.

## What to do
- Provision a cloud VM with ≥ 8 vCPU, 32 GB RAM, 200 GB disk in a region close to the operator.
- Configure a WireGuard VPN gateway on the VM. Add operator's device as the only allowed peer.
- Restrict SSH to listen only on the WireGuard interface; disable password auth, require key.
- Enable host firewall (ufw or nft): allow only WG handshake port from internet; allow SSH
  only via VPN; outbound unrestricted.
- Enable unattended security updates.
- Create the operator OS user (`op`) with sudo. Disable root SSH.
- Create base directories: `~/code/`, `~/.fabric/{infra,logs/sanitized}`.

## Acceptance Criteria
- [ ] VM is reachable via WireGuard tunnel only.
- [ ] `nmap -p 22` from a non-VPN host shows port 22 closed.
- [ ] `systemctl is-system-running` returns `running`.
- [ ] Operator user `op` exists with sudo; root login over SSH disabled.
- [ ] Base directories exist with correct ownership.
- [ ] Unattended security updates active.

## Verification Steps
**Smoke:**
- `ssh op@vm.internal 'systemctl is-system-running'` → `running`
- From a non-VPN host: `nmap -p 22 <vm.public_ip>` → port 22 filtered/closed
- `sudo ufw status` shows VPN-only SSH rule
- `cat /etc/ssh/sshd_config | grep -E '(PermitRootLogin|PasswordAuthentication)'` shows both `no`

**User:**
- Connect to VPN from your phone and SSH into `op@vm.internal`; confirm shell is functional.
- Disconnect VPN; confirm SSH and any other admin endpoint is unreachable.

## Details
**Files (to create on VM, not in this repo):**
- `~/.fabric/infra/wireguard/wg0.conf` — server config; allowed peer key for operator
- `/etc/ssh/sshd_config` — `ListenAddress wg0_ip`, `PermitRootLogin no`, `PasswordAuthentication no`
- `~/.fabric/infra/cloud-init.yml` — bootstrap script for repeatability

**Dependencies:** none (root of dependency tree).

**Edge cases:**
- Cloud-provider's default rescue console must stay available (out-of-band recovery).
- WireGuard handshake port should not be a common one (e.g., 51820 → randomized).

**Implementation hints:**
- Keep a sealed copy of the WG private key in Vaultwarden (created in Task 02).
- Snapshot the VM image immediately after this task — first "last-known-good" candidate.
