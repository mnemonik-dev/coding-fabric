# Task 04: Ansible role `kaneo`

## Required Skills
Before starting, load: /skill:ansible-automation

## Description
Install self-hosted Kaneo via docker-compose, reverse-proxied through the same Caddy
instance as Vaultwarden, and seed six default projects (one per protocol repo) idempotently
via Kaneo's HTTP API. Anchors tech-spec §2.3 role 4, user-spec §4.1.

## What to do
- `roles/kaneo/tasks/main.yml`:
  - extend docker-compose with Kaneo service (database + web)
  - add Caddy vhost `kaneo.mnemonic-fabric.ts`
  - wait for `/api/health` healthy
  - call `POST /api/projects` for each of: `mnemonic-core`, `mnemonic-mcp`, `mnemonic-wasm`, `mnemonic-demo-client`, `mnemonic-docs`, `mnemonic-loop` — idempotent via prior `GET /api/projects` check
- Healthcheck step asserts all six projects exist post-run

## Acceptance Criteria
- [ ] Role idempotent
- [ ] `curl https://kaneo.mnemonic-fabric.ts/api/health` returns 200
- [ ] Six projects present after first run, no duplicates after second run
- [ ] `ansible-lint` passes
